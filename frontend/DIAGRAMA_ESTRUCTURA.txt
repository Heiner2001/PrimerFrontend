                  └── No tiene estado propio

═══════════════════════════════════════════════════════════════════
                     🔄 FLUJO DE DATOS DETALLADO
═══════════════════════════════════════════════════════════════════

AGREGAR TAREA:
──────────────
Usuario escribe → Input (ListaTareas)
                     ↓
              onChange actualiza 'nuevaTarea'
                     ↓
Usuario click "Agregar" o presiona Enter
                     ↓
           agregarTarea() se ejecuta
                     ↓
         Crea objeto: { id, texto, completada }
                     ↓
           setTareas([...tareas, nuevaTarea])
                     ↓
         ListaTareas se re-renderiza
                     ↓
       map() crea componentes Tarea nuevos
                     ↓
         Cada Tarea.js recibe sus props


MARCAR COMPLETADA:
──────────────────
Usuario click botón ✓ en Tarea.js
            ↓
  onClick llama onCompletar(tarea.id)
            ↓
  Callback ejecuta marcarCompletada(id) en ListaTareas
            ↓
  map() busca tarea por id y cambia 'completada'
            ↓
  setTareas(nuevoArray) actualiza estado
            ↓
  ListaTareas re-renderiza
            ↓
  Tarea.js recibe nueva prop con completada: true
            ↓
  CSS aplica clase 'completada' (tachado)


ELIMINAR TAREA:
───────────────
Usuario click botón 🗑️ en Tarea.js
            ↓
  onClick llama onEliminar(tarea.id)
            ↓
  Callback ejecuta eliminarTarea(id) en ListaTareas
            ↓
  filter() crea nuevo array SIN esa tarea
            ↓
  setTareas(nuevoArray) actualiza estado
            ↓
  ListaTareas re-renderiza
            ↓
  Tarea.js se desmonta (desaparece de la UI)


═══════════════════════════════════════════════════════════════════
                          💡 CONCEPTOS CLAVE
═══════════════════════════════════════════════════════════════════

✓ ESTADO LOCAL: Cada componente maneja su propio estado
✓ PROPS: Datos fluyen de padre → hijo (unidireccional)
✓ CALLBACKS: Funciones se pasan como props para comunicación hijo → padre
✓ INMUTABILIDAD: Siempre crear nuevos arrays/objetos, nunca mutar
✓ KEYS: Cada elemento de lista necesita key única (usamos tarea.id)
✓ SEPARACIÓN: Un archivo por componente + su CSS
✓ REUTILIZACIÓN: Tarea.js se renderiza múltiples veces
✓ PRESENTACIÓN vs LÓGICA: Tarea.js solo presenta, ListaTareas gestiona
